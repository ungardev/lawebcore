## HALLAZGO #1 — Bug Crítico en get_balance() (Parser)

### El Problema

El patch de Opus 5 (Hito 23) en `get_balance()` buscaba:
```python
for key in ("balance", "balance_usd", "credits_usd", "amount"):
    if key in data:
        return float(data[key])
```

Pero HikerAPI retorna **cuando el saldo es $0**:
```json
{
  "state": false,
  "error": "Top up your account at https://hikerapi.com/billing",
  "exc_type": "InsufficientFunds"
}
```

**Ningún campo coincide → retorna `None` → pre-flight se omite → run procede → enrichment falla con 402 → $0.64 desperdiciados.**

### Validación con curl en Railway

```bash
curl -s -H "x-access-key: $HIKERAPI_API_KEY" https://api.hikerapi.com/v1/account
→ {"state":false,"error":"Top up your account at https://hikerapi.com/billing","exc_type":"InsufficientFunds"}

curl -s -H "x-access-key: $HIKERAPI_API_KEY" https://api.hikerapi.com/v1/user/balance
→ {"state":false,"error":"Top up your account at https://hikerapi.com/billing","exc_type":"InsufficientFunds"}
```

**Ambos endpoints existen y responden, pero sin campo `balance`.**

### Fix Aplicado (Hito 25)

```python
async def get_balance(self) -> float | None:
    for path in ("/v1/account", "/v1/user/balance", "/account"):
        try:
            client = await self._get_client()
            resp = await client.get(path)
            if resp.status_code != 200:
                continue
            data = resp.json()

            # HITO 25: detectar respuesta de saldo insuficiente
            if data.get("state") is False:
                logger.warning(
                    "hikerapi_balance_insufficient",
                    path=path,
                    exc_type=data.get("exc_type"),
                    error=data.get("error"),
                )
                return 0.0  # Activa pre-flight abort correctamente

            for key in ("balance", "balance_usd", "credits_usd", "amount"):
                if key in data:
                    return float(data[key])
        except Exception:
            continue
    return None
```

**Cambios:**
1. Detecta `state: false` → retorna `0.0` → pre-flight activa abort
2. Auth header ya configurado en `_get_client()` — no necesario duplicar
3. Logs de warning para visibilidad

## HALLAZGO #2 — Desfase Redis↔DB de $25.13

```
Redis: lens:budget:hikerapi:2026-08 = "3.2"
DB sum: SUM(actual_cost_usd) = $28.33
Diferencia: $25.13
```

**Causa:** Runs de ago-12 a ago-17 (antes de Hito 21) no crearon keys en Redis porque el sistema de budget tracking no existía. Redis solo muestra lo gastado desde ago-17 en adelante.

**Implicación:** BudgetFuse no es confiable para saber cuánto queda. El pre-flight lee `lens:budget:hikerapi:2026-08` pero ese número no refleja el gasto histórico real.

**Esto es un blocker para producción.** Sin budget tracking confiable, no sabemos cuándo se acaba el saldo hasta que llega el 402.

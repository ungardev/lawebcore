## 2. 🔴 EL BUG REAL: SE GASTÓ $1.64 SABIENDO QUE NO ALCANZABA

Esto no está en tu lista y es lo más caro del proyecto.

La secuencia del run fue:

1. Descubrimiento: ~32 llamadas → **$0.64 gastados**
2. Prefiltro: elige 50 handles
3. Enrichment: primera llamada → **402 Payment Required**
4. `step3_degraded = true`, el run continúa
5. Scoring sobre perfiles sin datos → 0 candidatos
6. **Total facturado: $1.64. Candidatos: 0.**

**El sistema nunca comprueba si hay saldo suficiente para completar el run antes de empezar a gastar.** `BudgetFuse.assert_budget_available()` valida el presupuesto *interno* (tu contador en Redis), no el saldo *real* de HikerAPI. Son dos cosas distintas y hoy nadie mira la segunda.

Verifiqué: **no existe ningún endpoint de balance en `hikerapi_client.py`.** No hay chequeo previo posible con el código actual.

### El fix

Un *pre-flight check* al inicio de `discovery_run_task`:

```python
# Estimar el costo del run antes de gastar nada
estimated_calls = discovery_calls_estimate + MAX_HANDLES_TO_ENRICH
estimated_cost = estimated_calls * settings.HIKERAPI_COST_PER_CALL_USD

balance = await instagram_source.get_balance()   # 1 llamada, o 0 si es endpoint gratuito
if balance is not None and balance < estimated_cost:
    raise SourceUnavailable(
        f"Saldo insuficiente: ${balance:.2f} disponibles, ~${estimated_cost:.2f} necesarios "
        f"para {estimated_calls} llamadas. Recarga en hikerapi.com/billing",
        status_code=402, provider="hikerapi",
    )
```

**Coste del fix: 1 llamada ($0.02). Ahorro: $1.64 por cada run que hoy arranca condenado.** Es el mejor retorno de todo el proyecto.

Si HikerAPI no expone un endpoint de balance, la alternativa: al recibir el **primer** 402 del enrichment, **abortar el run** en vez de seguir. Hoy sigue procesando y gastando en un run que ya no puede producir nada.
